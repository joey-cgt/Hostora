# 1. Layout Overview

整体采用「顶部婚礼氛围场景 + 中部双数据卡 + 下部左人物主体 + 右侧 About Me 标题与介绍卡 + 底部过渡留白」。

阅读顺序：顶部氛围场景 → 双数据卡 → About Me / 关于我 → 人物主体与介绍卡。

核心结构不可改变：

- 顶部为整宽婚礼氛围场景，只传达仪式环境，不出现可识别人物面部。
- 两张数据卡位于场景下方，同宽并列、同高对齐。
- 下部左侧只保留一个客户真实人物主体；不得增加辅助人物或第二照片。
- 下部右侧由 About Me / 关于我标题和一张个人介绍卡上下组成。
- 底部保留干净的背景延续空间。

# 2. Layout Structure

以下坐标以 1088 × 2176 成品画布为基准；X、Y 为页面百分比，包含模块内部留白。

| 区域 | X 范围 | Y 范围 | 内容与对齐 |
| --- | --- | --- | --- |
| 顶部安全留白 | 0%–100% | 0%–5% | 背景延续，不放核心信息 |
| 顶部婚礼氛围场景区 | 8%–92% | 6%–37% | 无可识别人物面部的仪式空间、花艺、纱幔、座椅或远景剪影 |
| 数据卡片 01 | 10%–45% | 40%–54% | 主持年限：大号数值、单位、指标名称，居中 |
| 数据卡片 02 | 55%–90% | 40%–54% | 主持场次：大号数值、单位、指标名称，居中 |
| 左下人物主体区 | 10%–44% | 58%–94% | 单一客户真实人物，半身或 3/4 身，向下延展 |
| About Me 标题区 | 50%–92% | 58%–66% | 第一行 About Me，第二行 关于我；右侧列对齐 |
| 个人介绍卡 | 50%–92% | 67%–92% | 客户身份、定位、特点或真实介绍文案，左对齐 |

## Area 01 — 顶部婚礼氛围场景区

该区用于建立婚礼主持的职业氛围。允许使用花艺、仪式通道、纱幔、舞台光影、宾客背影或远景剪影；不得出现可识别的人脸、虚构客户形象、具体项目名称、品牌或案例信息。

场景不得承载客户姓名、履历或数据，且不得压住下方双数据卡的阅读。

## Area 02 / 03 — 双数据卡片

左卡固定对应真实主持年限，右卡固定对应真实主持场次。每张卡按「大号数值 + 较小单位 + 指标名称」排版，两卡同宽同高。

数值仅能使用客户资料中的真实数据；缺失时保留对应位置留白。不得复制预览中的示例数字、添加“+”，或扩展为第三张数据卡。

## Area 04 — 左下人物主体区

仅使用一张客户原始照片，人物位于左下区域，采用半身或 3/4 身裁切。人物头部不可进入双数据卡区，轮廓不可遮挡右侧 About Me 标题和个人介绍卡。

允许裁切、背景融合、光影与色彩优化；不得改变客户脸部、发型、年龄、体态、服装职业属性或补全不存在的身体部位、配饰。

## Area 05 — About Me 标题区

固定为双行阅读关系：第一行 `About Me` 为主标题，第二行 `关于我` 为较小副标题。仅在客户 `copy.md` 提供对应标题时使用；缺失时保留区域留白，不自行补写。

标题位于右侧信息列上方，与下方个人介绍卡左边界对齐。可使用弱化短线或低权重、无事实含义的字母装饰，但不新增信息模块。

## Area 06 — 个人介绍卡

卡片承载客户提供的身份、定位、主持特点或真实经历短句，建议 4–7 行、左对齐。卡片样式的圆角、边框、材质和光影由指定 `style.md` 决定。

不得添加未提供的机构、荣誉、服务承诺、联系方式、案例、年限或场次数值。文案不足时保持卡内留白。

# 3. Background and Layering Rules

- 风格由指定 `style.md` 决定；B03 只控制结构，不绑定 preview 的黑白手绘效果。
- 层级由后至前：背景 → 顶部婚礼氛围场景 → 数据卡与个人介绍卡 → 左下人物主体 → About Me 标题与文字。
- 顶部氛围场景与左下人物主体不可形成两个同等权重的人物焦点；场景中不得出现可识别脸部。
- 仅双数据卡和个人介绍卡可使用容器。不得新增服务清单、荣誉墙、标签组、二维码、辅助照片或第二人物。

# 4. Information Hierarchy

1. 顶部婚礼氛围与双数据卡核心数值。
2. 左下人物主体与 About Me 标题。
3. 个人介绍卡中的身份、定位和特点文案。
4. 弱装饰与背景元素。

# 5. Alignment Rules

- 顶部场景与双数据卡使用同一内容安全边界。
- 两张数据卡的顶边、底边、内部文字基线一致。
- About Me 标题与个人介绍卡形成右侧信息列，左边界对齐。
- 人物主体保持左下视觉列，右侧文字不得覆盖人物脸部或身体主体。
- 页面底部至少保留 6% 空白过渡区。

# 6. Style Replacement Rules

允许替换：客户真实照片、客户提供文案与数据，以及指定风格下的色彩、字体、材质、光影和轻量装饰。

不允许替换：顶部场景、双数据卡并列关系、下部左人物右介绍卡关系、About Me 标题位置、画布比例、信息层级和底部留白。

# 7. Generation Constraints

- 成品画布为 1088 × 2176 px，比例 1:2。
- 个人介绍页必须调用 Workflow_B，并校验 B03、指定风格、客户资料和真实照片。
- 标题、身份、经历、数据、定位与特点文案必须来自客户资料；缺失时留白。
- 禁止 AI 生成替代客户照片或改变人物身份。
- 顶部场景不得出现可识别人脸或被理解为真实客户、真实案例的人物。
- 禁止生成手机外框、状态栏、图外批注、箭头、结构说明文字或尺寸标注。
- 禁止添加第二人物、辅助照片、第三张数据卡、服务列表、荣誉墙、标签组、二维码或其他未定义模块。

# 8. AI Prompt Reference

使用 B03_顶部婚礼场景+双数据卡片+左人物右介绍型，结合指定 `style.md`、客户 `profile.md`、`copy.md` 和真实照片，通过 Workflow_B 生成 1088 × 2176 px、1:2 竖版主持人个人介绍页。

顶部 6%–37% 放置无可识别人物面部的婚礼仪式氛围场景；在 Y 轴 40%–54% 并列两张同宽数据卡，左卡只放真实主持年限，右卡只放真实主持场次。下部左侧 X 轴 10%–44%、Y 轴 58%–94% 放置唯一的客户真实人物主体。右侧 X 轴 50%–92% 先放 About Me / 关于我双行标题，再放一张承载真实身份、定位和特点文案的个人介绍卡。底部保留约 6% 的干净过渡空间。

严格遵守上述区域关系。顶部长景仅为职业氛围，不能出现可识别人物；核心文案与数据只使用客户提供资料，缺失时留白。风格表现服从指定 `style.md`，不照搬 preview 的手机框、黑白手绘、状态栏或图外批注。不得新增模块，不得生成替代客户照片。
